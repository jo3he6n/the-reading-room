# The Reading Room v9 — 개인 계정과 기기 간 동기화

이번 버전은 v8의 독서 기록 기능(마지막 페이지 입력, 자동 쪽수 계산, 요일별 통계, 최애 책 표지)을 유지하면서 아이디·비밀번호 로그인과 클라우드 동기화를 추가합니다.

## 먼저 해야 할 일: Firebase 연결 (최초 1회)

GitHub Pages는 정적 호스팅이므로 계정과 기기 간 동기화를 위해 Firebase Authentication + Cloud Firestore를 사용합니다. 아래 설정을 한 번 완료하면 같은 아이디로 로그인한 폰·PC·태블릿에서 같은 서재를 사용할 수 있습니다.

1. [Firebase Console](https://console.firebase.google.com/)에서 프로젝트를 새로 만듭니다.
2. 프로젝트 개요에서 웹 앱(</>)을 추가합니다. 앱 이름은 `The Reading Room` 등 편한 이름으로 정하면 됩니다.
3. 웹 앱 설정 화면의 `firebaseConfig` 값을 복사해 저장소의 `firebase-config.js`에 붙여 넣습니다. `PASTE_...` 부분을 모두 실제 값으로 바꿉니다.
4. Firebase Console의 **Authentication → Sign-in method**에서 **Email/Password** 로그인을 활성화합니다. **Authentication → Settings → Authorized domains**에 `jo3he6n.github.io`가 없다면 추가합니다.
5. **Firestore Database**를 생성합니다. 지역은 가까운 아시아 지역을 선택하면 됩니다.
6. Firestore의 **Rules** 화면에 이 폴더의 `firestore.rules` 내용을 그대로 붙여 넣고 게시합니다.
7. GitHub 저장소 `jo3he6n/the-reading-room`의 루트에 아래 파일을 모두 올리고 커밋합니다.
   - `index.html`
   - `script.js`
   - `style.css`
   - `auth.js`
   - `firebase-config.js` (본인의 Firebase 설정값을 넣은 파일)
   - `firestore.rules` (참고용; 실제 규칙은 Firebase Console에도 게시해야 함)
   - 기존 `KcalliAutumnGothic.ttf` 폰트 파일은 삭제하거나 이름을 바꾸지 마세요.
8. GitHub Pages가 배포된 뒤 홈페이지에 접속해 **새 서재 만들기**에서 아이디와 비밀번호를 만듭니다.

## 계정 이용 방식

- 아이디는 영문·숫자·밑줄 3~20자입니다. 대소문자는 구분하지 않습니다.
- 비밀번호는 6자 이상입니다.
- 이메일 주소를 입력하거나 인증할 필요가 없습니다. 내부적으로 Firebase 이메일/비밀번호 인증을 사용하되, 아이디를 기반으로 사이트 전용 가상 로그인 주소를 만들어 사용합니다. 사용자에게 이메일을 보내지 않습니다.
- 같은 계정으로 로그인하면 책, 독서 날짜와 쪽수, 문장, 형광펜, 독서평, 위시리스트, 장르, 최애 책 선택이 동기화됩니다.
- 로그아웃하면 로그인 화면으로 돌아갑니다. 로그인하지 않은 기본 상태에는 예시 책이 표시되지 않습니다.
- 이메일을 사용하지 않는 계정이므로 비밀번호를 잊었을 때 본인이 이메일로 재설정할 수 없습니다. 비밀번호를 안전하게 보관해 주세요.

## 기존 기록 가져오기

- 기존 브라우저에 저장된 책 기록은 그 기기에서 처음 로그인할 때 새 계정으로 가져오도록 처리했습니다.
- 여러 기기에 예전 기록이 각각 저장되어 있다면, **각 기기에서 같은 계정으로 처음 로그인**하면 기존 기록을 클라우드 서재에 합칩니다.
- 브라우저 데이터/사이트 데이터 삭제 또는 시크릿 모드 사용은 피해주세요. 클라우드에 저장된 기록은 계정에 남지만, 아직 로그인하지 않은 기기의 로컬 기록은 삭제될 수 있습니다.
- v8의 `dailyEndPages` 데이터와 기존 `dailyPages` 기록 변환 로직은 그대로 유지됩니다.

## 보안 참고

- `firebase-config.js`의 웹 앱 설정값은 브라우저에서 사용되는 공개 설정값입니다. 실제 데이터 접근은 Firestore 보안 규칙에서 로그인한 사용자의 UID와 데이터 경로가 일치할 때만 허용합니다.
- Firestore Rules를 게시하지 않거나 위 규칙과 다르게 설정하면 동기화가 실패할 수 있습니다.
- 한 계정은 본인 서재를 여러 기기에서 사용하는 용도입니다. 다른 사람에게 비밀번호를 알려주면 그 사람도 해당 서재를 볼 수 있습니다.
